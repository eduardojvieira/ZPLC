## The single mechanism
`IDE/src/catalog/stdFunctions.ts` (new) turns the compiler's table into one record per registered name: input pins `[name, type]`, `returns`, `variadic`, category, en/es text. Named functions read `FUNCTION_DOCS`; a conversion is `IN : FROM`, returns `TO`, from `CONVERSION_TYPES`. The one fact the table lacks is kept beside it: `COPY.DST` and `CLEAR.S` are written by the call, with a test that pins it to the reference text. A test asserts that the records cover exactly `getAllFnNames()`.
- **FBD**: `classify` gets a last branch `isFn(type) -> 'stdfunction'`, after every current branch, so the 8 keep their code path and their ST. `getDefaultPorts` reads the record (no `OUT` for VOID). Emission: positional arguments in table order, `OUT := NAME(a, b);`; a concrete pin renders its source to its type; the generic pins of one call go through the existing `unify`, and a generic return takes that type (as `MAX`/`MIN`). An unconsumed result is still a call, `NAME(a, b);`, as for project functions today; VOID is always that statement. `portType` and `outputType` treat `ANY_BIT` and `ANY_INT` as generic. A generic pin checks its class (ANY_BIT: BYTE, WORD, DWORD, LWORD; ANY_NUM: integers and reals; ANY_INT: integers), and a mismatch is a clash naming the block. The compiler accepts `SHL(REAL)`, a `MUX` of mixed types and a literal `DST` for `COPY`, so the transpilers check types and written arguments themselves. An unwired pin, a type clash, and a written pin (`COPY.DST`) not wired from a variable block are errors naming the block and the pin.
- **Ladder**: `LD_FUNCTIONS` = the 15 entries as they are, plus one entry from the record for each of the 293 other names; new kind `function`: `IF <power> THEN <output> := NAME(<operands>); END_IF;`, ENO = power (LNG-028). VOID has no output and emits `IF <power> THEN WATCHDOG_RESET(); END_IF;`. The output follows the operands for `ANY*`; as in FBD, the transpiler checks the class of each generic operand whose type it knows (a declared variable or a typed literal) and a written operand, because the compiler does not; the compiler's other errors are mapped to the rung and cell. `EQ_STRING`/`NE_STRING` store a BOOL like any other function; the 6 comparison boxes stay the only ones that pass power on a result.
- **MUX inputs**: the document already stores the input ports of each FBD block. "Add input" and "Remove input" (context menu and keyboard command list of the block) append or drop `IN<n>`, never below `IN0`, `IN1`; the transpiler reads the ports of the document. A Ladder box gets the same two commands in its slot editor; `operands` grows, and validation accepts at least 3 operands (`K`, `IN0`, `IN1`) for a variadic record and exactly the pin count otherwise.
- **STRING operands in Ladder**: a declared STRING variable is accepted already. `OPERAND_LITERAL` (`transpiler/ldToSTValidation.ts:328`) gains the strict IEC literal `'(?:[^'$]|\$.)*'`, passed verbatim. A written operand (`COPY` `DST`, `CLEAR` `S`) must be a declared variable; a literal there is an error naming the rung and cell.

## Guards of point 5, as tests
- **Byte-for-byte ST**: commit 1a records, on unchanged code, the ST of every `.fbd.json` and every rung of every `.ld.json` in `packages/zplc-ide/lessons`, `packages/zplc-ide/projects`, `conformance/lng` and `tools/hil` (sha256 per file plus the text), and of the 23 synthetic fixtures, because no existing diagram uses FBD `MAX`, `NAND`, `NOR` or `MOD`; the test compares after every later commit.
- **Trace hashes**: before the first code commit, from `packages/zplc-ide`, `bun scripts/learn/sceneLessonTimings.ts --out $HOME/.cache/zplc-tmp/lng/base.json` (outside the repository, kept for the whole thread); at the end of each core unit `bun scripts/learn/sceneLessonTimings.ts --out $HOME/.cache/zplc-tmp/lng/end.json --compare $HOME/.cache/zplc-tmp/lng/base.json` (`--compare` without `--out` exits 2); any difference fails.
- **No codegen or C change**: the verifier checks `git diff --stat 7a713277 -- packages/zplc-compiler/src firmware` shows only the export lines of `compiler/index.ts`.
- **LNG-002, LNG-003**: one case per error kind (unwired pin, clash, written pin from a temporary, wrong operand count) asserts the message names the block, or the rung and cell, and that no ST is produced in its place.

## Generated tests (point 6)
- **Compile**: 297 diagrams and 297 rungs from the record, each built through `compileMultiTaskProject` with zero errors (594 cases).
- **Native differential** (U-LNG-2; needs `ZPLC_NATIVE_SIM_BIN`, as the existing native tests): per function one project with the example's `VAR` block as globals, and three programs in one task: ST `LngSt := NAME(ops)` (`LngSt := a MOD b` for `MOD`: the call form does not parse), the FBD diagram and the Ladder rung (powered) storing `LngFbd` and `LngLd`, then ST `LngSameF := LngFbd = LngSt` (`EQ_STRING` for STRING). After the example's scans both flags must be TRUE; the same scan gives `UPTIME` and `CYCLE_TIME` one value. `LngSt`, `LngFbd` and `LngLd` are declared with the type of the variable the reference example assigns the call to (a conversion: its `TO`). The operands are the arguments of the first call of `NAME` in `FUNCTION_DOCS[NAME].example.source`, taken with a balanced-parenthesis parse, because examples nest calls; for a conversion, the source value of `conversionExample(FROM)` (`tools/docs/generate_function_reference.ts:141`), which the docs job already runs. `WATCHDOG_RESET` is run for its scans without a fault.

## Risks
- STRING temporaries of FBD are declared without a length: a long `CONCAT` could truncate where an ST variable would not. The differential with the reference operands shows it; the fix is in the transpiler.
- The cost: 297 native projects. One forecast before the first run; batched per category if it is slow.
- The FBD palette gains 289 entries and the Ladder one 293; search and the grouped conversions keep it usable, and the reviewer judges the captures.
- **Owner stop (point 5)**: reading shows no function that needs a codegen change, since ST already calls all 297 with these signatures. If a compile or differential case fails only because of codegen, the run stops and asks the owner, naming the function. MUX and SEL on STRING are refused by today's code generator ('it is not a string'). In 2.1.0 the transpilers refuse them with an error naming the block, unless the owner asks for a codegen change (point 5).
